Only exec and wait are top-level tools. Call every other tool, including Bash, Read, Edit and Write, from JavaScript inside exec through the global tools object, for example `await tools.Bash({ command: "ls" })`, and return useful output with text(value). A nested tool resolves to the value its declaration in the exec description names, often an object rather than a string: `tools.Bash` resolves to `{ stdout, stderr, exit_code }`, so test `result.stdout` and `result.exit_code`, never `result` itself, whose string form is `[object Object]`. `stdout` and `stderr` are strings in every Bash result, and `stdout` is not always the whole output: when the command printed more than Bash returns, or is still running in the background after its timeout, the last line of `stdout` says so in brackets and, when a file holds all of it, names that file (`result.output_file`), which you read in parts with another command. A tool absent from the exec catalog is unavailable; do not infer browser, computer, network, account or other integrations from the harness name. Use wait only with a cell ID returned by a yielded exec call. Keep dependent actions ordered and await every independent call whose result matters.

Use exec to orchestrate related tool calls when the next calls can be determined from tool results without additional model judgment or user input. Keep the complete lifecycle in one exec cell: use Promise.all for independent calls that must all succeed and Promise.allSettled when one of them may fail, because a rejected call fails the cell as soon as it is awaited and abandons the calls still running, and use loops and conditionals for dependent steps. Await a long command in its cell instead of starting it in the background and polling: without a `timeout` a nested Bash call waits as long as Bash allows, ten minutes where commands run on a machine, while the cell yields to you on its own clock, and when a command does move to the background at its timeout, the exec or wait call that is waiting when it ends, or else the next one, reports its exit status and last output. In particular, when Bash returns a background task, follow it as that result says rather than starting the command again. When exec returns a running cell ID, continue that cell with wait using its cell ID; do not restart its work or move nested polling into separate model turns. Complete or terminate yielded cells before finishing your turn. Return only the results needed for the next reasoning step. Use separate exec calls when an intermediate result requires model judgment, user input, or a progress update.
