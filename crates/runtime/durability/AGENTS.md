Own session drivers, shared store actors, child journals and checkpoint catalogs over the core/durability contracts. Keep storage adapters out.

SessionStore::session, SessionStore::resume and DurableSession::open, open_shared, open_shared_described and open_sibling acquire ownership and fully persist the described record before returning, so the record is durably readable from the authoritative state and earlier owners are fenced at return. Index visibility is eventual and begins when the summary is published. Preserve these semantics.

SessionStore::prepare_session, SessionStore::prepare_resume and DurableSession::prepare_shared_described return a driver without acquiring ownership or writing to the store; prepare_resume validates the existing state and infers its record through non-fencing reads. The first command acquires ownership once through StateStore::acquire_with, merging the prepared record and, for acquire_agent_with_initial, the initial settings. The native JSONL adapter commits both with one full disk sync; adapters using the default fallback commit acquisition and replacement separately. Use prepared sessions only where backend construction consumes them immediately, such as runtime/agent spawn, fork and resume pipelines and backend lazy child executions, so agent construction stays fully synced before the agent is returned. Acquisition failures go to the triggering command; uncommitted failures may be retried and other failures poison the driver.

DurableSession::acquire_agent_with_initial_checkpoint commits a backend's initial checkpoint in the same acquisition replacement as the prepared record and initial settings, only when the stored state has no session record, checkpoint or operations; otherwise it returns InitialAcquisition::Existing and leaves the state as a plain acquisition would. Backend harnesses use it for fresh prepared sessions and fall back to their eager durability path for every Existing outcome, including records without a checkpoint or pending operations, so saved model and initial settings remain authoritative. DurableSession::seeded_child_journal returns a root journal and the JournalSeed that owns its pending tree acquisition only when the store reports batches_companion_acquisition, which SharedStore caches from its adapter at construction and reports as false on WASM; otherwise it returns the ordinary journal and an inactive seed so the tree acquisition keeps overlapping construction; deferred harness constructors keep the seed for the construction scope and give their execution only a JournalClaim. acquire_agent_with_initial_checkpoint_and_journal acquires the subagent tree through StateStore::acquire_with_companion only while that journal is already waiting in its first load, which happens only for the journal the subagent registry adopted, so the native JSONL adapter writes the tree acquisition, session acquisition and replacement with one full disk sync. The journal adopts the tree owner only after a successful acquisition; every acquisition error, an unawaited journal, a mismatched seed and dropping the seed when construction returns, fails or is cancelled leave the journal to acquire the tree itself, while the session reports and poisons on its own error as before. AgentRuntime::open_loaded reserves the root journal in the subagent registry before construction when the store batches companion acquisition; DurableSession::adopt_child_journal accepts only a seed from the same root and store and lets acquire_agent and acquire_agent_with_initial take it, so an eager resume writes the tree acquisition with the session acquisition in one full disk sync. The registry adopts a reserved journal on the root's first registration; a refused reservation, as for a root already restored or reserved in the process, keeps separate acquisitions, and dropping the reservation releases only its own journal and seed. DurableSession::described_record returns the record supplied at preparation without acquiring and is not proof that the state is empty.

SessionStore::prepare_resume_loaded prepares the same resume as prepare_resume for a StoredSession loaded from this store, rejecting a session from another store or whose identity changed after loading, and attaches the loaded checkpoint with its stored key without further reads. DurableSession::take_checkpoint_preload clears that preload and returns it only for the given acquired checkpoint key; backends must still prove the preload matches the acquired checkpoint content, as Codex does by re-encoding it to the same content-addressed key, and otherwise reload under ownership. Take the preload once after acquisition so it is not retained.

Startup durability is bounded by full disk syncs, about 5 ms each with F_FULLFSYNC on macOS APFS. Measure journal entries, sync count and latency for new-session construction when changing acquisition paths.

SharedStore forwards commit on both targets. SharedReader runs a StateReader behind its own actor so index and event reads are not serialized behind writes. MemoryStore implements both StateStore and StateReader and is the reference adapter; a clone of the same MemoryStore used as the reader shares one actor, so its reads and writes share one queue.

SessionReader wraps a StateReader for clients that hold no StateStore, such as remote hands reading sessions. It exposes query, events, search_events and read_records, plus state and resolve for read-only loads of the journal state and its payloads. SessionStore::with_reader attaches one, and SessionStore's query, events, search_events and read_records delegate to it; without a reader they return the unsupported non-fencing read error. query rejects a non-UTF-8 workspace and an indexed state whose decoded record names another session. The configured writer and reader must refer to the same logical store.

SessionRecord.metadata holds caller-owned JSON values and defaults to empty. SessionRecord::derive starts it empty, so forks and branches do not inherit per-session claims, and merging keeps the stored map unless the next record supplies a non-empty one. catalog::summarize owns the StateSummary mapping: value is the JSON SessionRecord, scope the UTF-8 workspace, parent the lineage parent, title the record title, preview the first admitted prompt, falling back to the first non-blank text of the session's committed events, and attributes model, family and origin by their Display or serde names. Only states with a session record that SessionStore::summary would list, because they have operations, a checkpoint, have committed events or are created children, receive a summary; a commit that makes a listed state unlisted removes it. The commit that first carries events marks the session record as having events and captures that event preview, bounded like prompt previews, in the same payload, so the mark and preview persist across resumes without rereading events, forks start without them, and older records load without them. A session with events therefore stays listed and is removed from the index only when its state is retracted; states committed before this rule are indexed on their next commit. Every driver commit carries the current summary; stores without an index ignore it.

DurableSession::stage queues a SessionWrite on the session driver without committing it, and an empty write queues nothing. The driver attaches every staged write, in staging order, to its next commit of any kind, including commits made through a live agent's DurableOwner, so the events and metadata commit atomically with that transition; hosts therefore stage immediately before the owner commit they intend to annotate. Staged writes are not durable until that commit. A NotCommitted commit keeps the staged events and metadata queued for the next commit; an uncertain outcome poisons the driver as for any other commit. DurableSession::append stages its write and commits immediately without changing operations, steps or checkpoints, so it is allowed while an agent generation is live, and append with an empty write flushes queued writes. DurableSession::commit_checkpoint stages its write and commits the standalone checkpoint in the same commit. When append or commit_checkpoint fails with NotCommitted, its write stays queued but the attempted checkpoint does not, so retrying with the same write duplicates its events; flush with an empty append instead. Both return a SessionReceipt with the revision, the seq range of every event in that commit, empty without events, and the resulting record. StateStore::supports_events reports whether commit records events, defaults to false, stays fixed for an adapter and is cached by SharedStore; when it is false, stage, append and commit_checkpoint reject a write with events with NotCommitted before queueing anything, while metadata-only writes remain allowed.

MetadataWrite is a data-only compare-and-set. Its optional MetadataExpectation lists metadata values, None meaning absent, and optionally the title, that must equal the current record. When the expectation holds, the write applies its TitleChange and sets or removes the listed values; otherwise it changes nothing while its events still commit, and the receipt record shows the winning values. Staging metadata requires a session record and otherwise fails with InvalidState. Identity fields cannot change through it. SessionWrite and the metadata types carry no serde derives; add them only when an RPC transport needs them.

Acquisition durably records the session record, and the index summary is published by a driver commit. With a reader configured, SessionStore::session and SessionStore::resume commit once after acquisition when the state is a listed session. prepare_session and prepare_resume write no summary of their own and publish on their next driver commit. Query visibility is eventual and never promised at return; sessions created before the index existed appear after their next driver commit. Session liveness and cross-session messaging belong to the host runtime, not to persistence.

StateStore::flush is an ordered adapter barrier, with a no-op default for adapters whose completed writes need no further work. SharedStore serializes it with reads and mutations; SessionStore::flush exposes it to SDK consumers without closing shared clones. Native storage adapters must keep blocking file work outside asynchronous runtime workers and complete accepted writes even when their response receiver is dropped.
